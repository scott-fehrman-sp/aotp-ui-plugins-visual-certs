## Decisions (each with rationale)

1. **Pure helper `src/graph/completedFilter.ts`**, exporting `isCompletedStatus(status?)`, `isCompletedEdge(edge)` and `withoutCompleted(graph): { graph: AccessGraphData; hiddenCount: number }`. Mirrors `referenceFilter.ts` (pure, no React, non-mutating, order preserving) so it is trivially unit-testable and memoizable.
2. **Reachability pruning, not descendant deletion** (as specified). Algorithm, all linear:
   - Completed edge = `edge.firstLevel && isCompletedStatus(edge.reviewStatus)` (`approved|revoked|reassigned`). `needsReview`, undefined status and mixed (aggregated needsReview) are never completed.
   - `hiddenCount` = number of DISTINCT `edge.to` among dropped edges (one per hidden first-level item). Refinement: an entitlement that is held directly (completed) AND nested under a visible role is counted as hidden (its reviewable card is removed) even though a muted reference copy stays.
   - If nothing was dropped, return `{ graph, hiddenCount: 0 }` with the SAME graph object (stable memo identity).
   - Else: remaining = edges minus dropped. Build `outgoing: Map<from, edge[]>` over remaining. BFS from every `kind === 'user'` node (visited set, cycle safe). Keep nodes in input order that were visited; keep every remaining edge whose `from` is visited (its `to` is visited by construction), input order.
   - **Demotion**: a kept non-user node that still carries `reviewStatus` but is no longer the target of a kept `firstLevel && reviewStatus` edge (its status edge was dropped, it survives only as lineage) is returned as a copy with `reviewStatus` and `reviewMixed` deleted (same technique as `userSubgraph`). That makes `isReferenceNode` true, so the scene draws it as a muted, non-selectable reference card with no status ring/icon. All other nodes keep object identity.
3. **Apply order**: completed filter first, then `withoutReference` (so with reference hidden only needs-review first-level items remain; demoted nodes are reference and vanish).
4. **State**: `showCompleted` (default `true`, in memory, NOT reset on user change or grid/drill-down switch, same as `showReference`). `completedResult = useMemo(() => subgraph ? withoutCompleted(subgraph) : null, [subgraph])` is computed whether or not completed items are shown so `hiddenCount` is always known (button label, announcement). `visibleGraph` memo picks `showCompleted ? subgraph : completedResult.graph`, then `showReference ? base : withoutReference(base)`. The scene builder is untouched and is fed the filtered graph, so lanes (role, access profile, entitlement, source) re-pack without gaps.
5. **Refit**: append the flag to the drill-down part of `fitKey` (`...|${rankdir}|${showCompleted ? 'done' : 'nodone'}`), so exactly one overlay-aware plan runs per toggle; nothing else in `FitOnSceneChange` / `fitPadding` changes. `sceneKey` also gets the flag so stale hover/focus is cleared (confirmed: `sceneKey` is the only clearing mechanism for emphasis; a status-only refresh that hides the hovered card is out of scope and `emphasizeEdges` is a no-op for an unknown id).
6. **Selection**: add an adjust-during-render clear right after `activeItemId` is computed: `if (inDrilldown && selectedItemId !== null && activeItemId === null) setSelectedItemId(null)`. This clears a selection whose item got hidden (or demoted to reference) so it does not silently re-activate when completed items are shown again, and does not announce anything stale (the toggle announcement replaces the live text). Selection of a still-visible item survives untouched. If `eslint-plugin-react-hooks` v7 rejects the conditional render-phase setState, fall back to clearing in `toggleCompleted` when hiding: `if (selectedItemId !== null && !withoutCompleted(subgraph).graph.nodes.some((n) => n.id === selectedItemId && n.reviewStatus)) setSelectedItemId(null)`.
7. **Notes**: `isDegenerate` stays computed from the UNFILTERED `subgraph`. New `allCompletedHidden = inDrilldown && !showCompleted && !isDegenerate && completedResult.graph.nodes.every((n) => n.kind === 'user')` renders `<Panel position="top-center"><p className="vc-graph-note">All access items are complete. Show completed items to see them.</p></Panel>` (same style/slot as the "No expanded access" note; the two are mutually exclusive). It is judged BEFORE the reference filter so the reference toggle cannot change which note shows. The ScrollHint's `itemCount` and the fit/readable-zoom decision already read the filtered `scene`; no change, only tests.
8. **Button**: fourth button between Reference and Minimap. Active/pressed = completed items SHOWN. Labels: shown `Hide completed items`; hidden `Show completed items` + ` (N hidden)` whenever a count is provided (including 0); grid disabled `Completed items (open a user to filter)`. In the grid `aria-pressed` still reflects the stored preference (same as Layout / Reference). Always enabled in drill-down, even with 0 completed items (simplest, predictable; hiding 0 is a harmless no-op that still refits once).
9. **Icon**: new inline SVG entries `completed` (circle + check) and `completedHidden` (dimmed check at `opacity=".4"` plus a full-opacity diagonal strike), same `stroke` props; add `data-icon={name}` on the `<svg>` for testability. No CSS needed for the icon. No other CSS expected (reuse `.vc-graph-control-active`, `.vc-graph-note`); only touch `AccessGraph.css` / `GraphControls.css` if the real-browser check shows a real problem.
10. **Announcements** via the existing `setAnnouncement`: hiding -> `Completed items hidden (N).` (N = `completedResult.hiddenCount`), showing -> `Completed items shown.`.
11. **Not decomposed into FEAT artifacts**: helper, button and canvas wiring are tightly coupled (the new required `GraphControls` props break the canvas compile until it is wired), the whole change is ~6 small source files, so the workflow's existing implement-and-review loop runs this plan as is. No `update_workflow` restructure.
