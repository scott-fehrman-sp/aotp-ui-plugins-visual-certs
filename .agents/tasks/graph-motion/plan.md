## Design decisions (rationale in one or two sentences each)

1. **Same algorithm as org-graph, two required deltas.** Class names are APPENDED (deduped, transition tokens stripped first) because edges/nodes carry status classes; a size guard `MAX_ANIMATED_NODES = 400` applies when previous displayed + next node count exceeds it (hundreds of simultaneously transitioning, doubled-DOM cards janks; the end state is applied instantly instead).
2. **Pure planning function.** All diff/phase logic lives in `planTransition()` (pure, unit-tested); the hook only schedules. This keeps the fragile timing code tiny.
3. **Motion 0 bypass.** When `motionMs === 0` the hook RETURNS the target frame directly (no state hop, no extra render) and only syncs its `displayed` ref. Every existing test (motion 0 in jsdom) then renders exactly what it renders today.
4. **Structural input only.** The hook is fed `scene.nodes`/`scene.edges` and `sceneKey`; `highlightEdges` runs AFTER the transition on `frame.edges`. Hover/selection can therefore never start a transition. Everything that reads the scene (selection validity, lineage, scroll hint, notes, counts, announcements) keeps reading the TARGET `scene`.
5. **Opacity premise of the brief verified false for this DOM; deviation recorded.** The brief says inline `style.opacity` from `dimEdge` would beat the stylesheet `opacity:0` of an entering/exiting edge. In React Flow 12.12 the inline style is on the inner `<path>` and the class is on the outer `<g>`, so the two MULTIPLY. Therefore: entering edges ARE restyled (no visual pop when the transition ends and selection/hover stays consistent); only EXITING edges are excluded from restyling and from the lineage walk (they are leaving, and must not be treated as live lineage). T7 checks this in a real browser; if it shows an unexpected opacity, fall back to skipping entering edges too and say so in the report.
6. **Staying-edge "settle" uses a CSS animation, not the `entering` transition.** A staying edge's `<g>` is already at opacity 1; adding `.entering` would start a transition toward 0 and removing it two frames later would reverse it with the CSS "reversing shortening factor" (about 30ms), so the fade-in would be invisible. A keyframe animation class `vc-graph-edge-settling` (0 to 1 over `--motion-ms`) has no such problem. Applied only to STAYING edges whose source or target node's displayed position differs from its target position (React Flow draws the edge at the FINAL geometry immediately while the card glides). Visual intent is identical to the brief's refinement; T4 compares with/without it and the report must say whether to keep it.
7. **Origins resolve multi-hop.** org-graph uses a neighbour that existed in the previous frame, else the neighbour's FINAL laid-out position. That would make a second-hop lineage card (access profile under an entering role) appear at its parent's destination. `resolveOriginPositions()` instead propagates origins outward from previously displayed cards, so every lineage card emerges from the user's card (T1: within 60px of the user card on the first frame). `originPosition()` keeps org-graph's exact single-node semantics and is the fallback.
8. **Camera = target bounds, gated on placement.** `FitOnSceneChange` stops reading `getNodes()`; it receives the TARGET scene nodes (ref, synced in an effect so it adds no trigger) and a `placed` boolean (every target node is in the frame at its target position and not `entering`). The fit effect does nothing until `placed`, so `fitView({ nodes: targetIds, ... })` reads final positions from the store and starts together with the cards' phase 2. Readable mode computes bounds/focus from the target nodes directly. The fit call stays `fitView`/`setViewport`, so existing spies and `padding` assertions keep their meaning (they gain `nodes` and `duration`). First fit uses `duration: 0`; later fits use `motionMs`.
9. **Motion duration source.** `readMotionMs()` parses `--motion-ms` (`450ms`, `0.45s`, empty, NaN gives 0). First render has no wrapper element yet, so the initial value is read from `document.documentElement` (the token lives on `:root`, the wrapper inherits it); a `matchMedia('(prefers-reduced-motion: reduce)')` change listener re-reads it from the wrapper. Test seam: optional `motionMs?: number` prop on `AccessGraphCanvas` overrides it.
10. **No flash on first mount.** The hook's initial state is already the staged frame (reveal classes) when `reveal==='stagger'` and `motionMs>0`, and `.reveal` hides the card without needing `.motion-on`, so the cards never paint fully visible first.
11. **Accessibility.** Exiting nodes/edges get `focusable:false`, `domAttributes: { 'aria-hidden': true, inert: true }` and pointer-events none. `inert` also blocks focus on the inner card (`tabIndex=0`). Live-region text comes from state (target). The staying user card is the same DOM element across grid and drill-down (same component type and position), so its focus survives.
