## Findings from exploring the worktree (these drive the decisions)

- `src/graph/tokens.css` defines `--ink --muted --line --accent --accent-soft --shadow --control --canvas --edge --sans` (light + `:root[data-theme='dark']`). **It does NOT define `--panel`** (org-graph does). `NodeTooltip.css` already handles this with `var(--panel, var(--control))`. Decision: do not touch tokens.css; use `var(--panel, var(--control))` for the toolbar and hint backgrounds (same precedent, resolves to `--control`).
- `AccessGraphCanvas.tsx` has no tests asserting the old layout button (grep for "Layout" / `vc-graph-toggle` in tests finds nothing), so no existing test needs its markup updated. Existing tests must stay green as-is.
- React Flow v12 `Panel` renders `position.split('-')` as classes (`top-left` becomes `top left`). The existing selector `.vc-graph-wrap .react-flow__panel.top-left` in `AccessGraph.css` therefore never matches. Do not rely on position-class selectors: give each panel an explicit `className`.
- `buildAccessScene.ts` already defines the two classifications this feature must reuse, inline: a node is reference iff `kind !== 'user' && !node.reviewStatus`; an edge is a status edge iff `edge.reviewStatus` is set (else reference). `userSubgraph.ts` stamps node `reviewStatus` only from the user's own `firstLevel` edge. A `firstLevel` edge with no matching review item has no `reviewStatus` and is ALREADY drawn as reference today.
- The window `keydown` Escape handler in `CanvasSurface` returns to the grid in drill-down. A focused toolbar button is not a "typing context", so Escape inside the new Hint would also leave the drill-down unless handled (see item 2).
- jsdom does no layout. Tooltip tests need the repo's scoped `stubRect` pattern (stub one element, never `Element.prototype`).
- `tsconfig.app.json`: `verbatimModuleSyntax`, `erasableSyntaxOnly` (no enums or parameter properties), `noUnusedLocals/Parameters`. Use `import type`.
- `vite.config.ts` serves HTTPS via basicSsl on 1573 by default; `--port 5199 --strictPort` overrides it. Chrome exists at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. `puppeteer-core` is not installed.

## Design decisions

1. **Where the reference filter lives:** new pure module `WT/src/graph/referenceFilter.ts` exporting `isReferenceNode(node)`, `isStatusEdge(edge)` and `withoutReference(graph)`. `buildAccessScene.ts` is changed to call the two predicates instead of its inline expressions, so "first-level vs reference" has exactly ONE definition that the renderer and the filter share (satisfies "do not re-derive first-level a second way"). Hiding reference therefore removes exactly what is drawn muted today.
2. **Filter semantics:** keep nodes where `kind === 'user'` or `!isReferenceNode(n)` (has `reviewStatus`); keep edges where `isStatusEdge(e)` AND both endpoints are kept. This removes nested-only nodes, all sources (never first-level), and all reference edges, and keeps a node that is both first-level and nested (its nested incoming edge is a reference edge and goes away). Never mutates input; preserves relative order; unknown/empty graph returns empty graph.
3. **Pipeline order:** `userSubgraph(graph, id)` (already overlaid) -> `withoutReference` when `showReference` is false -> `buildAccessScene(filtered, rankdir)`. Layout (dagre + lane de-overlap) is recomputed on the filtered graph, so no gaps.
4. **"No expanded access" note:** computed from the UNFILTERED subgraph (`isDegenerate` keeps using `subgraph.edges.length`), so hiding reference never triggers it for a user who has lineage. A user whose lineage exists but who has zero reviewed edges just shows the lone user card with reference hidden. The note moves from `top-right` to `<Panel position="top-center">`.
5. **State:** `showReference` (default true), `showMinimap` (default true) join `rankdir` as `useState` in `CanvasSurface`. None reset on `selectedUserId` change; the existing "reset to grid when `graph.nodes` changes" block is untouched and only resets `selectedUserId`.
6. **Re-fit:** `FitOnSceneChange` `sceneKey` becomes `inDrilldown ? \`${selectedUserId}|${showReference ? 'ref' : 'noref'}|${rankdir}\` : 'grid'`. Reference toggle re-fits as required. Adding `rankdir` is a one-token improvement so the layout toggle (now in the panel) also keeps the graph in view; minimap toggle does NOT re-fit.
7. **Announcements:** a second sibling `<p className="sr-only" aria-live="polite">` driven by an `announcement` state string (reusing the existing `.sr-only` class), set in the three toggle handlers. Not merged into the existing paragraph, because rewriting that text would re-announce "Showing access for one user" on every toggle. Messages: "Reference nodes and links hidden." / "...shown.", "Minimap hidden." / "Minimap shown.", "Layout changed to vertical." / "Layout changed to horizontal.".
8. **Hint:** local port in `ControlHint.tsx` (not shared with NodeTooltip, which stays untouched). Takes a single child element and `cloneElement`s `aria-describedby={open ? id : undefined}` onto it (a real child, unlike org-graph's inner span). The anchor is `<span className="vc-graph-hint-anchor">` with `display:inline-flex` (never `display: contents`). `show()` measures the anchor itself and bails ONLY if `rect.width === 0 && rect.height === 0`. Side `'left'`: point = `(rect.left, rect.top + rect.height/2)`, CSS `translate(calc(-100% - 8px), -50%)`. Opens on mouseenter and focus-capture; closes on mouseleave, blur-capture, and Escape. Escape calls `event.stopPropagation()` ONLY while the tooltip is open, so the first Escape closes the tooltip (and does not hit the window handler that leaves the drill-down); the second Escape behaves as today.
9. **Disabled buttons still get tooltips:** disabled `<button>`s can swallow mouse events, so `.vc-graph-control:disabled { pointer-events: none }` lets the hover land on the anchor span. Verify in the real browser (item 6).
10. **Button state conventions (org-graph parity):** `aria-label` equals the tooltip label and names the ACTION; `aria-pressed` reflects the on/off state; `.active` class when on (`.active:not(:disabled)` styled, disabled dimmed to .4).
    - Layout: label `rankdir === 'LR' ? 'Layout: vertical' : 'Layout: horizontal'`; `aria-pressed={rankdir === 'LR'}`; disabled in grid with label `Layout (open a user to change)`.
    - Reference: label `showReference ? 'Hide reference nodes and links' : 'Show reference nodes and links'`; `aria-pressed={showReference}`; disabled in grid with label `Reference nodes and links (open a user to change)`; icon `reference` (a small three-node lineage glyph; the muted/dim look of "off" comes from the unpressed state, no eye-off needed).
    - Minimap: label `showMinimap ? 'Hide minimap' : 'Show minimap'`; `aria-pressed={showMinimap}`; always enabled.
11. **Placement:** `<Panel position="top-right" className="vc-graph-controls-panel">`. Top-left keeps only "Back to all users" (`<Panel position="top-left" className="vc-graph-nav-panel">`, flex column, replaces the dead `.top-left` selector). MiniMap stays bottom-right, Controls bottom-left, legend panel bottom-left above Controls, note top-center. Toolbar is ~122px tall (3x32 + 2x6 gap + 12 padding + 2 border), so it clears the 150px minimap even at the 490px canvas height of a 1000x700 viewport.
