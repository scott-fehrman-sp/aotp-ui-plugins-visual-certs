## Diagnosis in one paragraph

Hypothesis H1 held. Since 9e62179 a card that first mounts with the `entering` class has its `<Handle>`s measured by React Flow while `.vc-graph-card` is `transform: scale(0.94)`, because the handles are CHILDREN of the scaled card. The card's size never changes when the scale animates back to 1, so React Flow never re-measures, and the `measured` field (added so edges do not blink) keeps the wrong offsets. Measured: with motion ON, endpoints are up to 7.61 px inside the card at zoom 0.82 and 16.72 px at zoom 1.8 (exactly `(1 - 0.94) x half-extent + 3.5` units x zoom); with motion OFF at 9e62179 and at 44435ae the stale-vs-DOM error is 0.00 (so the displacement is added by the motion path). H2 (lane wrapping, selection restyle) is ruled out by the 44435ae bisect. H3 also held, as a second, older defect: handles are positioned against the card's PADDING box, so the LR left endpoint is always 3.5 flow units inside (the 4 px left stripe) and the TB horizontal anchor is 1.5 units off centre; that is 2.87 px at zoom 0.82 and 6.30 px at 1.8 at 44435ae, motion OFF, and already breaks the new 1.5 px bar. The camera/zoom variant is dead (React Flow reads the zoom from the DOM). `measured` alone is not the cause (disabling it leaves 8.84 px).

## Chosen fix: candidate B (handles are no longer descendants of the scaled, bordered card)

Move the eight `<Handles />` out of the `<article className="vc-graph-card ...">` so they are direct children of the React Flow node wrapper (`.react-flow__node`: `position: absolute`, exactly 200x64, no border, never scaled). `AccessGraph.css`'s `scale(0.94)` rules already target `.vc-graph-card` only, so the visual effect is identical and the CSS needs NO change. One change fixes both defects: measured on a prototype, 0 failing endpoints in 256 runs (prod and dev, motion on and off), max |dxBorder| 0.90 px at zoom 1.8 (the 0.5-unit remainder is React Flow centring its 1 px handle on the wrapper edge; it is outside by at most 0.9 px, inside the 1.5 px bar), max |dCross| 0.00, `edge-vs-handle` 0.00, no edge blink (0 with motion ON, same as 9e62179), existing suite 49 files / 623 tests green. The prototype is `harness/protoB-reference.patch` (`git apply` it, or write the equivalent with the comments below).

Rejected, by evidence:
- A (`useUpdateNodeInternals` after settle): leaves H3 (6.30 px at zoom 1.8 with motion OFF), so it cannot pass 1.5 px alone; needs a "scale transition ended" signal and extra store updates. Strictly worse than B.
- C (explicit `node.handles`): not run; from the React Flow source, the mount-time ResizeObserver measurement (`force: true`) overwrites user handles and `internals.handleBounds` is preferred over `node.handles`; removing the DOM handles leaves `handleBounds = {source: null, target: null}` (truthy) and no handle is found.
- D: nothing else found.

KEEP unchanged (do not touch): `graphTransition.ts` including `withMeasured` (still what stops edges blinking: 592 -> 0), `useGraphTransition.ts`, `AccessGraphCanvas.tsx`, the scene builders and their golden positions, filters, review-status pipeline, `GraphControls*`, lane wrapping, `fitPadding.ts`, selection and hover, page-fill layout, `accessCounts`, `CampaignDashboard*`, `package.json`, `package-lock.json`, `AccessGraph.css` rules (only a comment may change). No new runtime dependency.
